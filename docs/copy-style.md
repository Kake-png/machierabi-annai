# 本文の書き方（駅ページの文章）

駅ページの要約・特徴・確認点・暮らしのメモを書くときの決まりです。2026-11-27 に全137駅の文章をこの決まりで書き直しました（変更履歴の「ブランチ `content/natural-copy`」）。

読む人は「◯◯駅＋テーマ」で検索して来て、知りたいことを早く見つけたい人です。読み物ではなく、**情報を取りに来た人が一度で分かる文** を目指します。

## 決まり

1. **結論や数字を先に書く。** 「多摩川の河川敷まで徒歩約3分」のように、何がどれだけ近いかを文の頭に置く。
2. **言い切る。読者への指示や助言の形にしない。**
   - 使わない：「〜に向いた街です」「〜を確認しましょう」「〜を歩いて確かめたい」「〜で判断しない方がよい」
   - 代わりに、その助言の元になっている事実を書く：「線路の東西で帰り道が変わります」
3. **1文に1つの情報。** 読点が3つ以上になったら、文を分けるか、名詞の並びを「・」でつなぐ。店と距離の並びのように3つ以上の項目は「／」で区切ると、ページ上で箇条書きになる（`assets/text-format.js`）。
4. **出典は文の最後にかっこで添える。** 「トクバイ：…」のように出典名から始めない。例：「…が並びます（GO TOKYO、2025-12-19更新）。」
5. **作業用語を書かない。** 次の語は言い換える。
   - 「道路網モデルで本線合流まで約N分」→「本線に合流するまで約N分（道路網から計算した目安）」
   - 「ランプ取付け部」→ 入口の向きだけ書く（「甲州街道から」など）
   - 「ポリゴン」→「両岸を合わせて約21.7ha」など
   - 「確認できず」→「見つからなかった」／「確かめられていない」（探して無かったのか、調べていないのかを区別する）
   - 「圏外」→「調べた範囲にはありませんでした」「徒歩◯分圏の外」（何の範囲かを書く）
   - 「集積なし」→「あまりない」
   - カタカナ語（スポット、ナイトライフ、マナー、エリアなど）は、日本語で言える場合は日本語にする
6. **調査のメモを書かない。** 「本文は有料で未読」「不採用（前回計測時）」「判定は変更なし」などは、読者に要らない。
7. **他の駅との比較を書くときは、掲載数に左右されない書き方にする。** 「12駅で最も高い」は、掲載が増えると誤りになる。数字（家賃など）だけを書く。
8. **同じ文を2つの欄に入れない。** 「休日」と「夜」、「街の表情」と「散歩・自転車」などで同じ内容になるときは、片方を1文の要約にし、詳しい説明（時刻・出典）はもう片方に置く。

9. **最初の画面の紹介文には、良い点だけを書く。** 見に来た人の全員が同じことを気にしているわけではない。マイナス面（「〜は見つかりませんでした」「〜だけです」「〜へは直通しません」）は「住む前に確認したいこと」に書く。紹介文が短くなるときは、その駅の特徴（24時間営業の店、公園や図書館までの分数、直通先など）から足す。

## 事実を変えないための約束

- 書き直しでは、**元の文章にない事実を足さない。** 正しいと分かっていても、データにない路線名・距離・評価は書かない（例：「東十条駅は京浜東北線」と補わない）。
- 「ない」「離れている」と言い切るのは、元のデータでそう確かめられているときだけ。元が「要確認」なら「確かめられていない」と書く。
- 書き直したら `scripts/copy-rewrite.py` で照合する。数字・英字・カタカナ語が消えていないか、元にない数字が増えていないかを機械的に確かめる。わざと消す語は `_drops` に書く。

```
python3 -I scripts/copy-rewrite.py export kameari,kitasenju > batch.json   # 書き出し
python3 -I scripts/copy-rewrite.py check  batch.json                       # 照合だけ
python3 -I scripts/copy-rewrite.py apply  batch.json                       # 照合して反映
```

## 残っている課題

- 固有名詞を並べる文（「サンロード、ハモニカ横丁、井の頭恩賜公園があります」など）は読点が多くなる。かっこの外に読点が3つ以上ある文は、全体の約2,900文のうち52文（1.8%）。
- 近隣駅が同じ飲み歩き先（北千住、赤羽、下北沢など）の紹介文を使うため、似た文が複数の駅に出る。
