## 解決済み

### 2026-11-27 文章がAIっぽく読みにくい（ブランチ `content/natural-copy`）
- 原因：調査メモの形（「施設A／施設B。出典名：…」）や、読者への助言の形（「〜しましょう」「〜を確かめたい」）、作業用語（道路網モデル・ランプ取付け部・確認できず）がそのまま本文に出ていた。掲載数が少なかったころの比較（「12駅で最も高い」）も残っていた。
- 対応：全137駅の本文を、事実を変えずに書き直した。書き直しの前後で数字・英字・カタカナ語を全駅照合した（問題0件）。
- 再発防止：文章を書くときは `docs/copy-style.md` の決まりに従い、`scripts/copy-rewrite.py check` で照合する。

### 2026-11-27 検索エンジン向けHTMLと画面の内容・順番のずれ（ブランチ `design/first-screen-facts`）
- 原因：駅ページはビルド時の静的HTML（JSなしで読まれる）を、ブラウザで別の順番・内容に描き直していた。静的HTMLには要点の数字や条件一覧がなく、写真が理由・出典より前にあった。
- 対応：静的HTMLを画面と同じ順番・項目に。定型文の置き換えと似ている駅カードは共通関数（`noteWithFacts`、`relatedCardBody`）で両方から出す。
- 再発防止：駅ページに項目を足すときは `app.js` の `renderStation` と `scripts/build.mjs` の `stationSeoHtml` の両方を直す（共通にできる部分は関数にする）。

### 2026-11-27 最初の画面に事実がない（ブランチ `design/first-screen-facts`）
- 原因：駅ページの最初の画面が、路線のラベル・見出し・説明文・ボタンだけで終わり、検索した人が知りたい家賃や条件の数が写真の下まで出なかった。
- 対応：見出しの直下に「1K家賃の目安／利用できる路線数／確認できた条件数」を数字で出す枠を追加（スマホ幅の最初の画面に入る）。条件チップ（#7で追加）と合わせ、根拠への入口も最初の画面にある。
- 追加対応：条件チップは6件まで表示し、残りは「ほか◯件」で開く。

### 2026-11-27 フォントがOS標準のまま（ブランチ `design/font-zen-maru`）
- 原因：CSSで指定した BIZ UDPGothic を読み込んでおらず、Macはヒラギノ、Windowsは游ゴシックで表示され、他のサイトと見分けにくかった。さらに `style.css` に `:root` の書体指定が2か所あり、後ろの指定（BIZ UDPGothic）が前を上書きしていた。
- 対応：Zen Maru Gothic（SIL OFL）を自前配信。使っている文字を含む分割ファイルだけを `public/assets/fonts/` に置き、`unicode-range` 付きの `fonts.css` を全ページの先頭で読み込む（`font-display: swap`、太さは400と700）。`--sans`/`--serif` を両方とも丸ゴシックにそろえ、見出しは字幅に合わせて大きさと折り返しを調整。
- 再発防止：文字を大きく追加したら `python3 -I scripts/subset-fonts.py <@fontsource/zen-maru-gothic>` を再実行する（含まれない文字はOS標準フォントで表示される。表示は崩れない）。書体指定は `style.css` の末尾の `:root` が最終的に効く点に注意。

## 再発防止

1. **ページの状態を調べるときは、本番URL（またはプレビューURL）か、`npm run build` 後の出力を見る。** コミットされた `public/` のHTMLだけを見て判断しない。
2. **スマホ用のCSSを書いたら、実際にスマホ幅（390px）で表示して確認する。** 同じ詳細度の指定は後に書いたものが勝つので、ファイルの後ろの方に同じ要素の指定がないか検索する。
3. **「A／B／C」のような羅列は、文字列でつなげずに、項目の一覧として扱う。** 表示側で崩れたら、データの持ち方から見直す。
4. **新しい種類のページや文章を足すときは、スマホの最初の画面で、利用者の知りたい事実（家賃・路線・該当条件）が見えるかを確認する。**
5. **文章を足すときは、出典名・日付・英語の名称を本文に混ぜず、出典欄に分ける。** 本文の書き方は `docs/copy-style.md` に従う。
6. **CSSやJavaScriptを変えたら、キャッシュ用の版数を更新し、`npm run check` を通す。** 検証が版数を固定で見ているので、更新を忘れると検査が失敗する。
7. **見出し・ラベル・キャプションの文末に「。」を付けない。** 「。」は文章の本文だけに使う。
8. **見出しと本文は、色や太さだけでなく、位置（字下げ・線）でも分ける。** ページ内で同じ見せ方に揃える。
9. **色を指定するときは、ライトモードとダークモードの両方で確認する。地図のように、画像だけを加工している部品は、背景色も同じように揃える。** 文字色と背景色は必ず対で指定し、コントラスト比を計測する（本文は4.5以上）。ライトモード用の色を足したら、ダークモード用の上書きも足す。
10. **押せる部分は、見た目の範囲と当たり判定を揃える。** 小さなアイコンだけを押せる形にしない。
11. **直した課題は、このファイルの「解決済み」に、日付・原因・対応を書く。** 原因を書いておけば、同じ型の問題を探しやすくなる。
