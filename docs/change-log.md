- 影響範囲：どのページ・ファイルに効くか

## 2026-11-28 ／ Claude ／ ブランチ `design/mobile-map-first`

- 変更：スマホでトップページを条件なしで開いたとき、一覧ではなく地図から始まるようにした。地図の駅名ラベルは、乗り入れ路線の多い駅から順に、重ならない範囲で表示し、入りきらない駅は小さな点にする。拡大すると、点だった駅にも駅名が出る。
  - キャッシュ用の版数：app.js v=89、interface-v34.css v=88。
- 理由：運営者の指摘。スマホで開くと地図より先に駅の一覧が出てきて、どんなサイトか分かりにくい。
- 何を気にしたか：
  - **地図を先にするだけでは足りなかった。** 試したところ、137駅の駅名ラベルが重なって読めない状態が最初の画面になった。
  - **全部を点にすると、地名に慣れていない人は場所が分からない。** 最初は引いた状態の駅を全部点にしたが、運営者から、東京育ちでない限り駅名が隠れると場所が分からないという指摘があった。そこで、池袋・品川・中野のような目印になる駅（路線が多い駅）の名前は残し、そのまわりの駅だけを点にする方式に変えた。駅名ラベルは点より前に表示する。
  - **条件つきで開いたときは一覧のまま。** 共有されたURLや検索から来た人は、絞り込んだ結果を見たいはずなので、条件が空のときだけ地図から始める。テーマのページとPCの表示は変えていない。
  - **点にした駅が、本来の位置から約500m南にずれていた。** 実機のスマホで運営者が気づいた（中央線の線路と駅の点が合わない）。駅の座標のデータは路線データと一致していた（中央線の各駅で0〜30m、全駅の中央値は5m）。原因は、駅名ラベルを点に縮めたときに、ラベルの枠の中で中央に揃っておらず、縦に4px（この縮尺で約500m）下がっていたこと。点を枠の中央に固定して直し、ずれが縦横とも0になることを全点で実測した。
  - **拡大していくと、駅名が「出る→消える→また出る」と行き来していた。** 運営者の指摘（三鷹が引いた状態で名前、少し寄ると点、さらに寄ると名前）。ズームのたびに重なりを一から判定していたため、その時々で隣の駅（吉祥寺・武蔵境）が先に場所を取っていた。駅ごとに「このズーム以上なら名前を出す」値を先に計算する方式に変え、拡大すると名前は増えるだけで減らないようにした。優先順は、路線数が多い駅から、同じ数なら駅の英字名順で固定。4段階拡大して、どの段階でも前の段階の駅名がすべて残ること、縮小すると元に戻ることを確認した。
  - **駅名ラベルも、実機のスマホ（iPhone）では線路より約15px下に出ていた。** 点を直したあとの実機のスクリーンショットで、点は線路の上に乗ったが、ラベルだけ下にずれていた。パソコンのChromeではずれが出ず、ブラウザごとの描画の違いだった。ラベルも点と同じく、枠の中央に固定する書き方にして、ブラウザに左右されないようにした。Chromeでは全ラベルでずれ0を確認したが、iPhoneのSafariはこちらで動かせないため、実機での再確認が必要。
- 影響範囲：スマホ幅（720px以下）のトップページ。条件を変えたときにも、ラベルを並べ直す。
- 未確認・今後：実機のスマホでの操作感（点の押しやすさ、地図タイルを含めた見え方）。サンドボックスでは地図タイルを読めないため、背景の地図は未確認。路線数が同じ駅の優先順は、データの並び順のまま。

- 理由：運営者の指摘。AIが書いた文章は抽象的で、「〜しましょう」のような助言の形や読点が多く、量産サイトのように見えて読みにくい。検索で来た人が情報をすぐ取れる文章にしたい。
- 何を気にしたか（判断の方針）：
  - **事実を変えない。** 書き直しの前と後で、数字（距離・分・金額・日付・番号）、英字、カタカナ語が1つも消えていないことと、元にない数字が増えていないことを、全駅についてプログラムで照合した（`scripts/copy-rewrite.py`。結果は問題0件）。わざと消した語は、駅ごとに理由をつけて記録した（下の一覧）。
  - **足さない。** 正しいと分かっていても、データにない情報は書き足さなかった。「ない」「離れている」と言い切ったのは、元のデータで確かめられているものだけ。書き直しの途中で、両国・不動前・瑞江の導入文で元のデータより強く言い切っていたことに気づき、元にある数字（徒歩16分、徒歩18分など）に合わせて直した。
  - **結論と数字を先に書く。** 「〜に向いた街です」「〜を確認しましょう」「〜を歩いて確かめたい」のような、読者への助言の形をやめた。代わりに、その助言の元になっている事実を言い切りで書いた。この型の言い回しは16か所あり、すべてなくした。
  - **出典は文の最後に。** 「トクバイ：…」「GO TOKYO（日付）：…」のように出典名から始まる文が325か所あった。中身を先に書き、出典はかっこで最後に添える形にした。前のPRで入れた仕組みで、日付つきの出典は小さく薄い文字で表示される。
  - **作業用語をなくした。** 「道路網モデル」33か所、「ランプ取付け部」43か所、「確認できず」64か所、「圏外」20か所、「要確認」3か所を、読者に通じる言い方に変えた（言い換えの表は `docs/copy-style.md`）。「確認できず」は、探して無かったのか（見つからなかった）、調べていないのか（確かめられていない）を区別して書き分けた。
  - **古くなった比較を消した。** 「8駅で最も高い」「12駅で最も安い」のような比較が21か所あった。掲載が少なかったころの比較で、137駅になった今は誤りなので消した（家賃の数字は残した）。
  - **同じ文を2つの欄に入れない。** 「休日」と「夜」、「街の表情」と「散歩・自転車」、「日常の用事」と「街の表情」で、同じ文がそのまま入っている駅が多かった。片方を1文の要約にして、時刻と出典つきの詳しい説明はもう片方に置いた。「交通」欄に要約がそのまま入っていた駅は、路線の情報だけにした。
  - **読点を減らす。** 名詞だけが3つ以上並ぶ文は「・」でつないだ（36駅）。ただし、もとから「・」を含む路線名（中央・総武線など）や、対の並び（「JRと京急、東口と西口」）は、かえって読みにくくなるので読点のまま残した。店と距離が並ぶ文は「／」区切りに戻し、ページ上で箇条書きにした（10駅）。
  - **テストが確かめている言葉は残した。** 板橋駅の「徒歩圏」をいったん「歩いて行ける範囲」に言い換えたらテストが落ちたため、元の語に戻した。
